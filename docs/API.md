# API
One FastAPI backend serves three
APIs. The full machine-readable description is [`openapi.json`](openapi.json) (OpenAPI 3); on a running
development or testing installation (`ENVIRONMENT` other than `production`) the interactive version is at
`/api/docs`; in production it is switched off, so the map of the API is not public.

| API | Prefix | Who | Authentication |
|---|---|---|---|
| Dashboard API | `/api/admin/*`, `/api/auth/*` | the dashboard (and integrations acting as a staff account) | session cookie |
| Bot API | `/internal/*` | the bot process only | `X-Service-Key` header |
| Health | `/health/*` | Docker, monitoring | none (closed to the internet by Plesk) |

## Conventions
* JSON in, JSON out, UTF-8. Moments are ISO 8601 in UTC (`2026-10-25T12:34:29+00:00`).
* Translatable fields are objects `{"en": "…", "ru": "…"}`.
* Lists are paginated: `?page=1&size=50` (max 200), the answer has `items`, `total`, `page`, `size`.
* Errors: HTTP status + `{"detail": "<code>"}` — a stable machine-readable code (`not_found`, `no_permission`,
  `transition_not_allowed`, `bad_email`, `rate_limit`, …). The dashboard translates the codes into all languages.
  Validation errors (422) carry FastAPI's field list.
* `401` — not signed in or the session ended; `403` — signed in, but the role does not allow it (`no_permission`)
  or the request came from another site (`invalid_origin`); `429` — rate limit.

## Authentication of the dashboard API
```http
POST /api/auth/login
Origin: https://support.example.com
Content-Type: application/json

{"username": "anna", "password": "…", "code": "123456"}
```

* `code` is needed only when the account has two-factor sign-in (the first answer is `401 code_required`).
* The answer sets the `session` cookie (`HttpOnly; Secure; SameSite=Strict; Path=/api`). Send it with every call.
* Every changing request (`POST`, `PUT`, `PATCH`, `DELETE`) must carry `Origin` equal to `ADMIN_ORIGIN` (CSRF
  protection). Server-to-server integrations send that header explicitly.
* `POST /api/auth/logout` ends the session. A password, role or block change ends all sessions of the account.
* For an integration, create a dedicated staff account with a custom role that has only the permissions it needs;
  everything it does is in the audit log under that name.

Example — tickets waiting for an agent, in Python:

```python
import httpx

base = "https://support.example.com"
with httpx.Client(base_url=base, headers={"Origin": base}) as api:
    api.post("/api/auth/login", json={"username": "crm-sync", "password": "…"}).raise_for_status()
    page = api.get("/api/admin/tickets", params={"status": "pending_agent", "size": 100}).json()
    for ticket in page["items"]:
        print(ticket["number"], ticket["subject"])
```

## Bot API
Used only by `bots/` through `bots/client.py`; documented for completeness and for adding channels
(see [GUIDES.md](GUIDES.md#several-bots-and-other-channels)). Every call sends `X-Service-Key: <BOT_SERVICE_KEY>`;
the key is compared in constant time. Plesk returns 404 for `/internal/` from the internet.

## Health
* `GET /health/live` — the process is up.
* `GET /health/ready` — database and Redis answer (used by the Docker healthcheck).
